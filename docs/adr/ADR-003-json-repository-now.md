# ADR-003 保留 JSON 存储，以仓储接口隔离

- 状态：已采纳（SQLite 作为后续演进）
- 日期：2026-11-26
- 决策者：第六组

## 背景

v1 直接读写 `data/db.json`，没有事务边界。替换为 SQLite 可以提升一致性，但 12 小时内迁移数据与重写全部查询风险过高。

## 决定

本次保留 JSON 文件，但只允许 `infra/db` 访问；业务层通过仓储接口读写。写操作统一包裹在 `transaction()` 中，采用临时文件加原子改名。

## 理由

1. 数据规模小，单文件足够；
2. 仓储隔离后，替换 SQLite 不影响 service 与 domain；
3. 12 小时内优先保证业务正确性与可演示性。

## 后果

- 并发写入仍受限，需在文档中声明"课程规模、单进程"；
- 所有新代码禁止直接 `fs.readFile('data/db.json')`；
- 替换 SQLite 时只实现新的 repository 适配器。
