# 系统说明

项目：高校课程协作与评审平台
小组：第六组（石尚、吕柯锋、裘文涛、呼垚彬）
课程：软件工程
阶段：系统实现 — 熟悉业务系统
版本：v1.0（2026-11-07）

---

## 1. 系统简介

面向软件工程等项目制课程，把「教师发布项目任务 → 学生组队 → 按迭代推进 → 提交成果 → 同伴互评 → 助教过程检查 → 教师终评 → 发布与导出成绩」整条链路放到线上完成，并保留全过程记录。

系统按《需求规格说明书 v2.0》实现，业务规则编号（BR-xx）与状态转换编号（ST-xx）与需求文档一一对应。

## 2. 角色与权限

| 角色 | 主要权限 | 明确不能做的事 |
|---|---|---|
| 学生 | 加入课程、创建或加入小组、提交迭代进度、组长正式提交成果、组间/组内互评、查看本人成绩 | 不能查看其他小组提交物（BR-01）；不能查看队友个人分（BR-08） |
| 组长 | 学生全部权限 + 代表小组正式提交、管理成员 | 不能替教师评分 |
| 助教 | 查看所负责小组、记录过程检查、参与进度跟踪 | 不能修改教师评分、不能发布成绩（BR-11） |
| 教师 | 建课、发布项目任务与迭代、分配互评、终评、发布与导出成绩 | 只能管理本人课程（BR-10） |
| 管理员 | 全局数据与基础数据维护 | 预留角色，当前演示未提供独立账号 |

所有权限校验均在**后端**完成，前端隐藏按钮不作为权限依据。

## 3. 功能实现情况

| 编号 | 功能 | 实现情况 | 关键接口 |
|---|---|---|---|

| M-2 | 学生组队与成员管理 | ✅ 创建小组、加入小组、容量校验（3—5 人）、移除成员、**组长移交（半数表决 + 教师确认）** | `POST /api/projects/:id/teams`、`POST /api/teams/:id/leader-transfer` |
| M-3 | 迭代任务与里程碑 | ✅ 迭代阶段创建、小组进度更新 | `POST /api/projects/:id/iterations`、`POST /api/teams/:id/progress` |
| M-4 | 项目成果提交 | ✅ 组长提交、版本递增、截止后拒绝 | `POST /api/submissions` |
| M-5 | 同伴互评 | ✅ 教师分配、3 份小组互评、组内互评、匿名展示 | `POST /api/projects/:id/assign-reviews`、`POST /api/assignments/:id/review` |
| M-6 | 助教过程检查 | ✅ 记录检查项、得分与结论 | `POST /api/checks` |
| M-7 | 教师评分 | ✅ 按四个维度终评，折算 0—100 | `POST /api/projects/:id/teacher-grade` |
| M-8 | 成绩汇总与导出 | ✅ 权重 20/20/60、缺项归一化、个人贡献系数、CSV 导出、**成绩申诉与冻结** | `GET /api/projects/:id/grades`、`POST /api/projects/:id/appeals` |
| M-9 | 通知与提醒 | ✅ 站内通知、未读计数、标记已读 | `GET /api/notifications` |

## 4. 系统架构

```
浏览器（原生 HTML/CSS/JS）
        │  fetch JSON / Bearer Token
        ▼
server.js（HTTP 服务 + 静态资源）
        │
        ▼
lib/api.js（路由 + 权限 + 业务规则）
        │
        ├─ lib/grades.js   评分引擎
        ├─ lib/activity.js 通知与过程记录
        └─ lib/store.js    JSON 持久化（原子写入）
                │
                ▼
          data/db.json
```

分层约定（见 `AGENTS.md`）：

1. HTTP 层（`server.js`）只负责请求解析、静态资源与统一响应格式。
2. 业务层（`lib/api.js`）负责权限、状态流转与规则校验。
3. 数据层（`lib/store.js`）负责集合读写与持久化。

## 6. 关键业务规则实现

| 规则 | 实现位置 | 行为 |
|---|---|---|
| BR-01 数据可见性 | 各查询接口的成员校验 | 学生访问其他小组时返回 403 |
| BR-03 小组人数 3—5 | `POST /api/teams/:id/join` | 超过 `teamMax` 拒绝 |
| BR-04 / BR-14 截止锁定 | `POST /api/submissions` | 超过 `dueDate` 返回"迭代已截止（ST-09）" |
| BR-05 三份互评 | `POST /api/projects/:id/assign-reviews` | 每份提交分配给其他小组，最多 3 个 |
| BR-06 匿名互评 | 数据只返回评语与得分；教师端可见评审人 | 学生不可见 reviewerId |
| BR-08 成绩可见性 | `GET /api/my/grades` | 仅返回本人与团队分 |
| BR-11 助教边界 | `POST /api/checks`、发布接口角色校验 | 助教发布成绩被拒绝 |
| BR-12 组长提交 | `POST /api/submissions` | 非组长返回 403 |
| BR-17 版本不覆盖 | `submissions.version` 自增 | 历史版本保留 |
| BR-19 / BR-20 组内互评与贡献系数 | `lib/grades.js` | 系数 = 个人分 ÷ 队内平均分 |
| BR-22 权重 | `lib/grades.js` | 互评 20% + 过程 20% + 终评 60% |
| BR-23 缺项处理 | `lib/grades.js` | 按已有分项归一化并标注"成绩未完整" |
| BR-24 导出 | `GET /api/projects/:id/export.csv` | 逐行到人，含系数与最终分 |
| BR-26 过程留痕 | `lib/activity.js` | 所有写操作调用 `log()` |

## 8. 五分钟演示路径

1. **教师登录**（teacher / 123456）→ 概览看到 1 门课程、1 个项目、4 个小组、2 个待终评。
2. 进入「项目任务」→ 看到 3 个迭代；点「分配同伴互评」生成任务。
3. 切到**学生**（student1，组长）→「迭代提交」提交迭代 2 成果 → 版本记录新增一条。
4. 切到**评审方学生**（student5）→「同伴互评」看到待评任务 → 打分并提交。
5. 切到**助教**（ta）→「过程检查」给第一组打分 90。
6. 切回**教师**→「评分与成绩」看到互评分、过程分、总分 → 点某组「终评」→ 提交 → 「汇总并发布成绩」。
7. 点「导出成绩（CSV）」，用 Excel 打开，逐行到人，含贡献系数与个人最终分。
8. 「过程记录」查看刚才所有操作的时间线。

## 9. 已知限制

| 限制 | 说明 |
|---|---|
| 数据存储 | 单文件 JSON，适合课程规模（百人以内）；不适合高并发 |
| 文件上传 | 不支持，成果以仓库链接与附件链接形式提交（与需求 BR-16 一致） |
| 定时提醒 | 未接后台定时任务，通知以站内记录形式存在；48/24 小时触发需部署时接入 |
| 邮件 / 短信 | 未接入 |
| 身份认证 | 平台内账号，未接学校统一认证 |
| 部署 | 单进程 Node 服务，未做多实例与反向代理 |
